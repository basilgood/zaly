# Zaly Rewrite — Architecture and Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild zaly so it is *simpler* and *easier to maintain* without losing any current functionality (persistent sessions, permissions, compaction, tools, multi-provider auth, TUI, plugins, resources).

**No MCP adapter by design:** zaly has no MCP layer; **plugins are the extension mechanism**, the analogue of MCP tools. `@zaly/plugin` is the stable public contract plugin authors code against. This plan preserves that.

**Current reality (measured, not guessed):**

- 9 packages, ~50k lines of `src` TS. `tui` is 16k, `agent` 10k, `ai` 7k, `cli` 5k.
- Layering is already clean and acyclic: `shared → ai → agent; {config, tui, plugin} → cli`. This is worth keeping.
- Biggest complexity is not coupling — it's *size of single files* (`agent.ts` 895, `tasks.ts` 839, `providers/*` ~800 each) and *duplicated generated schema* (`config` + `tui` each ship `schemas/{gen,tpl}`).

**Rewrite stance:** Do NOT rebuild the hard-won edges from zero — *port* them (fast JSONL resume, compaction pressure, tool batching/grace, permissions presets, terminal image degradation, prefix-cache awareness). The rewrite is a *restructure*, not a rediscovery.

## Target architecture

Collapse 9 packages → **6** (published; `dev` is internal). The invariant we keep: dependency graph stays acyclic and points downward toward `shared`.

| Package | Role | vs current |
| --- | --- | --- |
| `@zaly/shared` | Paths, env, process, text/ansi/json/yaml, find, cache. **Unchanged.** | keep |
| `@zaly/ai` | Providers, models, auth, content parts, streaming, validation. | refactor, mostly keep |
| `@zaly/agent` | Loop, session, tools, permissions, compaction, tasks, subagents. The state machine. | major refactor |
| `@zaly/tui` | Reactive core, widgets, render, input, markdown, themes, images. | split internally |
| `@zaly/config` | Settings, resources, packs, **plugin source manager** (npm/git URIs, install), skills, commands. | keep |
| `@zaly/plugin` | **Public extension API + loader** — the only package plugin authors depend on. | keep, rename `Plugin` |
| `@zaly/cli` | The app: composer, actions, replay, providers, permissions UI, widget glue. | thin, stays thin |

`@zaly/dev` stays as the internal dev dispatcher (not published).

**`@zaly/plugin` stays a separate package — do not merge it into config.** It is the published host boundary (`access: public`, ships `dist/`): the `PluginApi` handed to a plugin module at load time. External plugin authors must depend on *only this* tiny package to type `default function plugin(zaly: PluginApi)`, never the whole config/settings stack.

**Two distinct "plugin" concepts — keep them apart:**
- `@zaly/plugin` — the *runtime extension contract* (loaded module, `PluginApi`, loader via jiti).
- `@zaly/config/plugin` — the *source manager* (`Plugin`/`PluginStore`: npm/git URIs, install/update/dispose).

This mirrors VS Code's `@types/vscode`: the extension API is its own published package, cleanly separated from app internals.

## What gets ported as-is (do not redesign)

- Backward JSONL read + incremental resume + `lineOf`.
- Compaction (summarization) — the *sole* context-reduction mechanism. Masking stays deleted.
- `Tasks` background batch runner: streamable promotion, parallel chains, grace timing, ownerRound suppression.
- Permissions presets (`strict/readonly/permissive/yolo`) + allow/ask/deny escalation.
- Provider request shaping (OpenAI vs Anthropic content/part normalization, reasoning effort).
- Terminal image degradation (kitty → iterm → none).
- Split-phase `App.start` (paint UI before agent loads).

## Refactor priorities

### 1. Split `@zaly/tui` (16k → three cohesive modules under one package)
It currently does four jobs. Split by subpath export so one file change doesn't drag in shiki/markdown:
- `tui/core` — reactive (`signal`/`effect`/`store`), render tree, state. No markdown.
- `tui/widgets` + `tui/renderer` — box/input/select/tree/overlay; stream/surface/frame/selection/terminal.
- `tui/markdown` + `tui/shiki` — markdown render, code highlight, images. Lazy-loaded.
- Input handling (`tui/input`) can stay with `widgets`; themes (`tui/themes`) with `renderer`.

### 2. `tui` split — NOT NEEDED (verified)
Heavy deps (shiki worker, markdown rendering) are already lazily loaded; widgets use only `import type` for markdown/shiki; functional subpaths already exist. Skipping the module split — no measurable win.

### 2b. Break up `agent/src/agent.ts` (895) and `tasks.ts` (839)
Extract collaborators, keep the loop the owner:
- `Loop` — `#loop`/`#turn`/stop policy/status transitions.
- `QueueSink` — the three input queues (`inject`/`append`/`notify`) + `send`/`scheduleWakeup`.
- `ToolRunner` — `#runTools`, batching, tool-result commit, `#toolContext`.
- `PermissionGate` — `#need` escalation.
- `compaction/` and `session/` already are modules; keep them.

### 3. Collapse generated-schema duplication
`config` and `tui` each hold `schemas/{gen,tpl}` feeding validation + defaults. Make **one** schema source-of-truth per domain; derive both the validator and typed defaults from it. Removes ~3k lines of drift-prone near-duplicates.

### 4. Declarative config picker (`cli/src/app/config.ts`, 416)
Make the `/config` UI data-driven: `{prop, type, options, desc, notify}` rows → generic render + toggle. Delete the hand-wired per-prop renderers.

### 5. Resolve the `Plugin` name collision
Both packages export something called `Plugin`, and `cli/app/plugins.ts` imports both into the same file (`:4` type from config, `:13` runtime from `@zaly/plugin`). Rename `@zaly/plugin`'s loaded module to `LoadedPlugin` and its return type accordingly. Keep the two packages separate.

### 6. Single-source plugin API
Export the plugin surface from exactly one entry point (`@zaly/plugin`); have `cli` and docs reference it.

## Risks

- **Provider content normalization is subtle** — port `ai` first and lock it with the existing provider tests before touching it.
- **Prefix-cache behavior** — any change to how messages are projected (e.g. queue draining order) affects caching. Preserve current ordering.
- **`tui` split can introduce render regressions** — keep the renderer/stream/frame untouched during the module split; touch only import paths.

## Definition of done

- 6 published packages, acyclic deps, `@zaly/plugin` removed.
- Same CLI flags, config keys, session format, and plugin behavior as today.
- `bun test`, `z lint`, `z build` all green; test count ≥ current.
